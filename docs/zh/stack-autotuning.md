# 全栈自动调优：公共控制器与首批端到端接入

## 1. 解决什么问题

自动调优（autotuning）是在多个**语义相同的实现**中，先检查结果，再测量耗时，为当前设备和输入选择实现。这里的“全栈”是让算子、融合图和完整应用路径共用选择规则、环境识别、缓存和报告，而不是只看某一个 GPU 内核的执行时间。

例如，矩阵乘实现 A 的内核较快，却需要先整理输入布局；实现 B 的内核略慢，却能直接读取原布局。默认的完整路径计时会包含候选内部的布局整理和分配，避免只比较内核而选错。融合层比较整个融合候选；生成层比较从提示词处理到结束的完整生成方案。

本轮提供公共基础设施和首批真实调用路径，并不意味着仓库内所有库都已接入，也不是枚举整个模型全部内核组合的全局最优求解器。

## 2. 已接入的实际路径

| 层级 | 接入位置 | 比较对象 |
|---|---|---|
| 公共运行时 | `ruda/src/runtime/tune/stack/`、原 `LocalTuner` | 校验、预算、配对计时、缓存、并发控制、失效和报告 |
| 矩阵乘 | `ruBLAS/src/tensor_matmul/tune/base.rs` | 所有符合原选择条件的候选组；包含精度策略和真实布局 |
| 注意力 | `ruDNN/src/attention/tensor/tune.rs` | 整个注意力算子；区分掩码、偏置和算子选项 |
| 前向卷积 | `ruDNN/src/convolution/tensor/forward/tune.rs` | 整个前向卷积；以显式参考实现为基线 |
| 融合图 | `ruda-fusion/src/device/optim/matmul/tune.rs` | 已融合矩阵乘候选的全部对外输出，而不只是中间乘法 |
| 完整生成 | `ruLLM/src/autotune.rs` | packed 模型的 Portable 与 Automatic 两种完整贪心生成方案 |

已有 `TunePlan` 的候选资格规则继续保留；新路径展开所有合格优先级组，不再因为第一组能运行就停止搜索。候选数和总调优时间仍受预算约束，因此不保证试完每种实现。

尚未接入新控制器的 FFT、稀疏算子、求解器、通信算法以及其他融合优化保持原行为。没有新增批次大小、执行流数量、模型切分或多卡放置搜索。

## 3. 启用方式

必须在模型加载、工作线程启动和首次计算之前，显式安装一次公共控制器。示意入口：

```rust
use ruda::runtime::tune::stack::{enable_stack_autotune, Mode, StackPolicy};
use std::path::PathBuf;

let tuner = enable_stack_autotune(
    StackPolicy { mode: Mode::Explore, ..StackPolicy::default() },
    Some(PathBuf::from(".ruda-stack-cache")),
)?;
```

传入 `None` 表示只保留进程内缓存。是否允许磁盘复用，还取决于环境识别是否完整。全局控制器不能重复安装，也不支持运行中重新配置。

使用融合层时启用 `ruda-fusion/device-stack-autotune`；张量后端使用 `ruda-tensor-device/stack-autotune`。ruLLM 暴露 `stack-autotune` 特性并转发到下层。新路径依赖桌面或原生系统的标准库支持，不覆盖 WebAssembly 和无标准库配置；原有路径仍保留。

三种模式含义不同：

| 模式 | 行为 |
|---|---|
| `Explore` | 使用有效缓存；未命中时，在预算内校验和搜索 |
| `CacheOnly` | 不进行新的计时搜索；未命中使用显式参考实现。首次读取磁盘结果仍要做一次正确性检查 |
| `Disabled` | 参与新控制器的算子直接使用显式参考实现，不校准、不读取新缓存 |

不调用 `enable_stack_autotune` 才是完全保留原 `LocalTuner` 路由。`Disabled` 不等同于恢复旧自动调优器。未登记新元信息的算子继续走旧路径。

## 4. 选择和计时规则

默认策略：必须能验证输出；2 次预热；7 组参考与候选的配对样本；最多 32 个候选；每个工作负载 30 秒软预算；最小提升门槛 1.05 倍；相对中位绝对偏差上限 0.15。中位绝对偏差用于排除计时过于抖动的候选，不是严格的统计显著性检验。

每一组采样都重新测量参考和候选，交替先后顺序，计算“候选耗时 / 参考耗时”。用这些比值的中位数选优，而不是把不同时刻的一次最快结果直接比较。1.05 倍是**选优策略门槛**，不是已经实测出的性能提升。

默认 `Timing::EndToEnd` 在候选执行前后明确等待设备完成。候选内部的分配、布局转换、提交和完成等待计入耗时；为避免污染真实请求而创建的试跑输入位于计时区间之外。`Timing::Device` 使用现有设备分析路径和完成等待；完整生成校准只接受 EndToEnd。

预算在试跑结束后检查，不中断运行中的设备任务。参考实现校验、一次长内核以及完整生成的底层预热均可能超过该预算；它不是请求超时或硬实时限制。

内存缓存命中不再强制同步、读回结果或重新计时，保留正常异步提交。缓存键生成、锁和查询仍有主机开销，本环境未测量这些开销；不要把它描述为零开销。磁盘冷命中校验和首次探索会同步并增加延迟，适合离线或启动阶段校准。

## 5. 正确性与试跑状态

每个适配器必须声明参考实现；候选与参考使用同一数值输入，但可写输出和状态彼此独立。

矩阵乘的试跑输出现在单独分配，并保留原步长、视图偏移和完整分配跨度。旧的 `out.copy()` 可能读取尚未写入的输出，并把有步长的视图转换为连续布局，导致测量的不是实际工作负载。只读左右输入可以共享。

融合输出校验覆盖对外可见输出，检查类型、形状和数值；缓存键使用相对图编号查找实际张量，再读取真实句柄，不把绝对分配编号当成稳定图身份。生成试跑每次创建自己的 KV 缓存，不推进在线请求的历史状态。

默认浮点绝对容差是 1e-4，相对容差是 1e-3。比较使用缩放形式，避免计算误差本身时溢出，拒绝 NaN 和无穷大。参考实现和候选有相同错误仍可能通过相对校验，所以还需要独立高精度参考和设备测试。

默认参考与候选合计读回上限为 64 MiB。超过上限、量化输出缺少量化器感知的比较，或输出类型没有实现校验时，标记校验不可用，仅使用声明的参考实现，不宣传已经验证。明确的错误数值或参考执行失败直接报错，不能当作“没有校验器”放行。

`require_validation = false` 允许调用者显式承担未校验候选风险，报告中的 `verified` 仍为 false。生产配置不建议关闭校验。

完整生成校准要求校准提示词上的生成 token 编号和结束结果完全一致。token 是模型处理文本的编号单位，不一定对应一个字。这不是对全部提示词、全部 logits 或独立 FP32 数学正确性的证明。

## 6. 环境和缓存身份

键中包含操作和候选版本、原后端设备标识、设备能力、驱动身份、源码与构建指纹、运行时选项、数据类型、真实形状与步长、视图偏移、精度策略、操作参数和执行上下文。融合键还包含图内容；完整生成包含不可变权重版本、模型配置、提示词摘要、生成配置及底层选择摘要。

NVIDIA 在 Linux 上组合实际驱动发行信息、CUDA API 兼容版本、设备名称和构建 Toolkit 标记；AMD 组合 HIP 运行时、设备名称、内核驱动模块和操作系统内核信息；CPU 尝试读取型号及指令集。识别失败时默认只允许进程内缓存。

WebGPU、自研后端以及这些系统文件不可用的平台并未自动获得可靠驱动身份。后端可实现新增的默认方法 `Runtime::autotune_driver_fingerprint`。也可在启动前设置以下部署标记，但此时准确性由部署者承担：

```bash
export RUDA_AUTOTUNE_DRIVER_TAG='实际驱动或自研运行时的不可变构建标识'
export RUDA_AUTOTUNE_BUILD_TAG='部署产物与动态编译依赖的不可变构建标识'
export RUDA_AUTOTUNE_CONTEXT_TAG='实际负载、并发、拓扑与功耗配置标识'
```

额外驱动标记与已探测值组合，不覆盖已探测的真实版本。构建指纹覆盖工作区源码、清单、锁文件、Rust 编译器和编译环境，但没有保证捕获每个动态加载的 NVRTC/HIPRTC 库、下游外部候选实现或部署编译器变化；这类变化需要可靠的额外构建标记。

运行中不支持修改这些标记或设备配置。默认上下文名 `isolated-single-device` 只是默认假设，不代表程序自动测出了并发或拓扑。

磁盘记录放在所提供目录下的 `stack-autotune-v1`。默认有效期 7 天、容量 1,024；保留完整键，校验长度和内容摘要，损坏、过期、版本不符或未来时间戳按失效处理。写入通过临时文件和重命名提交；不能完成替换时保留旧文件并记录警告。只清理专属目录内的自身缓存记录。

摘要是非密码学哈希，不能用于签名、抵御恶意篡改或声称提示词匿名化。缓存和报告应放在可信、受权限保护的目录，不跨不信任租户共享。完整键验证避免仅凭文件名哈希碰撞误选，但提示词与依赖摘要不是密码学身份保证。

## 7. 并发、嵌套和故障

同一进程同一设备的调优只允许一个在途任务；全局默认也只有一个，可配置不同设备并行调优的上限。没有跨进程 GPU 排他锁，外部进程仍可能扰动测量。

竞争请求不等待调优锁，而走显式参考实现。嵌套调优只允许读取已有缓存；未命中走参考，避免递归探索和互锁。上层完整生成先预热两种计划的底层算子，再固定底层选择进行上层计时。

这是对**新共享调优器**的约束，不是对整个设备上所有业务提交的隔离；尚未接入的旧调优器也不受它统一管理。因此仍应在受控负载下校准。

设备完成状态未知时标记该调优通道故障，停止后续共享调优选择。它不重置 GPU，不修复驱动，不保证回收未知在途物理资源，也不捕获所有分配 panic。实际请求只执行一次，发生同步执行错误后使未来选择失效，不偷偷改用另一内核重播当前请求；异步错误需要上层归因和处理。

候选可声明临时工作区需求，设置 `workspace_limit` 后没有可靠估计的候选会被拒绝。当前算子适配器并未提供这些内存估计，因此开启硬工作区限制会连同参考实现一起拒绝，不会自动推导显存需求。默认不启用该限制。试跑输入和读回还有额外内存；这不是完整显存不足恢复机制。

## 8. 性能回退与依赖失效

`StackTuner::record_comparison` 接收调用者在**相同条件且正确性通过**时取得的参考/已选实现配对完成耗时。默认累计 7 组，中位耗时比大于 1.15 后，使该选择失效，并禁止该候选在当前键上继续入选；参考候选不会被禁用。

这影响后续 `select`，不修改已经返回的结果。接口不会自行重放线上请求、额外执行影子模型或自动调节负载。业务已经持有 `GenerationPlan` 时，要显式重新校准或退回参考模式，不能认为缓存失效会自动修改这个值。

`GenerationPlan::lower_levels_unchanged` 仅检查下层选择摘要是否变化，不证明这个上层计划自身未被撤销。摘要保守包含所有当前控制器中的有效下层选择，因此无关工作负载也可能引发重新校准；未接入的新/旧算子不在此依赖追踪中。

## 9. 完整生成示例

先确保模型目录已存在。示例不下载模型，也不会把目录名自动当成权重身份。`WEIGHTS_REVISION` 应来自不可变权重清单的内容摘要或同等可靠标识。

```bash
MODEL_DIR=/实际模型目录
WEIGHTS_REVISION=实际不可变权重清单摘要

# NVIDIA：执行离线或启动校准，再按选中的模式运行一次真实请求。
cargo run --release --locked -p ruda-llm \
  --features nvidia,stack-autotune --example qwen2_autotune -- \
  "$MODEL_DIR" "$WEIGHTS_REVISION" '解释一下矩阵乘法' 16 .ruda-stack-cache explore

# AMD：对应的 HIP 构建环境和设备。
cargo run --release --locked -p ruda-llm \
  --features amd,stack-autotune --example qwen2_autotune_amd -- \
  "$MODEL_DIR" "$WEIGHTS_REVISION" '解释一下矩阵乘法' 16 .ruda-stack-cache explore
```

这两个示例即使同时开启 nvidia/amd 特性，也分别使用明确的后端类型。`cache-only` 可替换最后的 `explore`，但显式调用完整生成校准仍包含底层预热和必要校验。不要将该校准函数放进每个 token 或每个在线请求的热路径。

示例以 JSON 行报告胜出模式、来源、是否校验、耗时比、样本数、噪声和实际请求耗时。不能把一次模型示例的耗时当成通用性能结论。

## 10. 兼容性与范围

既有生成函数、LocalTuner 入口、主要配置字段和旧缓存校验和继续保留。新 trait 方法有默认实现，新增能力通过构造方法和 Cargo 特性显式开启。原 `LocalTuner::clear` 仍只清理旧缓存；新缓存应通过控制器的 `invalidate` 等接口管理，不能把两者混为一谈。

修改了矩阵乘试跑输出的构造和旧预热错误传播，即使未开启新控制器，这两处问题修复也会生效。因此“未启用时保留原路由”不是逐行为、逐性能绝对不变的承诺。所有 API 和 feature 兼容性仍需实际编译测试。

不包含所有库的适配、跨卡通信调优、单模型多卡切分、服务级动态批处理、真正的全局组合搜索、自动收集线上配对基准或所有硬件上的数值/性能保证。

## 11. 验证入口

```bash
# 独立 Python 参考 + 编译和运行真实的 std-only Rust 核心测试。
python3 tools/run_stack_autotune_validation.py --suite reference --suite core

# 真实 LocalTuner 接入与旧运行时回归。
python3 tools/run_stack_autotune_validation.py --suite runtime

# 融合层、新旧特性、NVIDIA / AMD / 双后端构建。
python3 tools/run_stack_autotune_validation.py --suite feature-compile

# 必须在对应真实硬件和工具链上分别运行。
python3 tools/run_stack_autotune_validation.py --suite gpu-nvidia
python3 tools/run_stack_autotune_validation.py --suite gpu-amd
```

缺少工具会记录 `NOT_RUN` 并返回退出码 3，而不是跳过后标记全通过。运行失败或超时返回非零退出码；默认只运行 reference 与 core 两层。新增主机 CI 只执行这两层，没有假装配置了可用 GPU 自托管执行器。

当前源码包含 64 个可独立编译的实际 Rust 核心测试、1 个真实 LocalTuner 主机适配测试，以及每后端 3 个真实 GPU 矩阵乘测试。核心测试包含缓存边界、坏参考错误、计时、嵌套、并发和失效等。GPU 测试覆盖 F32/F16/BF16，每个含两个非连续输入形状；这远不是全算子硬件矩阵。
